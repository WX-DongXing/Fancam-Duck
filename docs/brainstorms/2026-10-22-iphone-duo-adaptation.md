# iPhone Duo 适配审视与重新设计

日期：2026-10-22。状态：已按用户草图接入原生预览工作台；设备验收与实际结果见验证指南。

## 最新设计约束（以用户提供的布局草图为准）

2026-10-22 最新草图替代此前文字推断。保留设置面板内部的画幅分段、三列整数读数、四个操作按钮及现有间距，不新增占比滑条或全高检查器。

- 外屏：视频在左上，进度条在视频下方；右侧系统导航区域承载竖向三工具。面板覆盖视频底部和进度条，收起后恢复进度条操作，不挤压视频。
- 内屏横向／书本展开：视频横向占主体；底部左侧为进度条、右侧为横向三工具。打开面板时浮在右侧工具上方，播放控件向视频左侧移动；进度条始终可见。
- 内屏竖向：视频在上方；底部进度条和横向工具上下排列。面板与工具等宽、在工具上方 12pt 打开；按后续截图确认，展开时覆盖进度条，收起后恢复进度条，播放控件从视频下方移入视频底部。
- 面板打开／收起保持画布几何、项目、时刻与参数；同工具再次点击关闭，工具切换仍互斥。

此前固定检查器、各姿态一律底部同列以及进度条隐藏规则均作废。下方初版方案仅作历史问题记录，不作为实施依据。当前 HTML 是可切换布局和构图面板开关的概念稿，非设备像素或原生材质验证。折叠曲面、安全区和实际 API 支持仍需在原生实现时检查。

## 官方依据

- [Designing for iPhone Duo](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo)
- [Design for iPhone Duo](https://developer.apple.com/videos/play/tech-talks/111466/)：外屏 compact、内屏 regular；按安全区与 size class 自适应；侧置系统栏；各姿态保持功能及层级一致。沉浸视频可跨全屏，但交互必须避开遮挡。
- [Strike a pose with adaptive layouts](https://developer.apple.com/videos/play/tech-talks/111463/)：Arrangement 分配两个内容区域；GeometryProxy reservedRegion 用于自定义交互的 division／occlusion 避让。平展时 division 可不活跃，不把设备中点当作恒定铰链。

## 当前实现与缺口

1. WorkspaceLayout.swift:5–10：360pt 画布 + 360pt 面板 + 20pt 间距，另要求高度至少 440pt。它是当前内容阈值，不能代表 Duo 姿态；regular 宽度但容器不足时会改成纵排。
2. EditorView.swift:697–703 与 ExportView.swift:31：仅按 regular 启用展开内容，与上述排列决策分离，可能让纵排布局承担全高检查器。
3. WorkspaceLayout.swift:22：已有 ArrangementView，但依赖 FANCAM_DUCK_NATIVE_ARRANGEMENT；当前工程文件未检出该标志。默认路径仍是 AnyLayout。
4. EditorView.swift:248：52pt 自绘顶部 HStack，不会获得系统 toolbar 的自动侧置行为；不能直接假定将随 Duo 自动迁移。
5. EditorView 的自绘播放控件、时间轴及面板未查询 reservedRegion。AnyLayout 本身不能证明半折时会避开曲面。
6. HomeView 已有 compact 列表／regular 项目库，ExportView 已有视频／输出设置分区，方向可复用。仍需覆盖分屏、窗口缩短及动态字体。
7. 本机当前 Xcode 27.1（27A9275），旧验证文档的 27.0 API 限制为历史信息；需通过实际 SDK 编译验证原生分支。

## 重新设计

| 场景 | 视频与交互布局 | 保持的行为 |
| --- | --- | --- |
| 外屏 compact | 视频占主体，系统返回／导出随 toolbar 安排；紧凑时间轴与工具 dock 在内容安全区内；面板覆盖视频下部并避开保留区 | 三工具互斥；关闭面板恢复时间轴；视频大小不随面板开关变化 |
| 内屏平展 regular | 视频与检查器两区，检查器容纳时间轴、工具选择、当前参数；由 Arrangement 分配空间 | 同一时刻、同一参数、同一播放意图 |
| 书本半折 | primary 与 secondary 分居 division 两侧；时间轴和所有按钮完整留在各自区内 | 不把播放按钮或滑块横跨曲面；功能不增减 |
| 桌面半折 | 视频在上区，播放、时间轴、工具和参数在下区 | 完整编辑能力，不生成独立的姿态专属流程 |
| 分屏／窗口缩短 | 跟随当前容器与 size class 压缩；面板内容必要时局部滚动，视频和主要操作保持可见 | 手机工作台根视图不滚动；不靠缩小触控区塞入内容 |

播放控件与时间轴归入控制区，避免随着折叠横跨曲面。构图的直接拖动／缩放仍在视频内；映射必须以实际视频区域坐标计算。系统栏使用语义 toolbar 分组，不手工添加固定间距；不能把三个工具当作应用顶层 Tab。

首页：外屏列表、内屏自适应网格，导入入口保持相同层级，项目卡片避开折叠区域。导出：复用同一分区容器，视频与画质／生成／保存操作分区，不改变编码和保存链路。确认人物：提示、上一处／确认／下一处、重新识别／手动框选放在 controls 区，身份阻塞保持有效。

## 方案取舍

推荐原生 Arrangement + 系统 toolbar + 自定义控件的 reservedRegion 避让。保留 AnyLayout 作为旧 SDK／旧系统与 Catalyst 的兼容路径，但不把兼容路径称为已完成 Duo 原生适配。仅调整固定断点成本较低，不能解决折叠避让；按机型做四套页面会增加切换时状态丢失风险，不采用。

## 实施顺序与验收

1. 核验 SDK 的 Arrangement、reservedRegion 与 toolbar API，编译现有原生分支；统一容器和内容的布局决策。
2. 提取复用的画布／控制区域，使用稳定视图身份，不因尺寸变化重建播放器或启动分析。普通 iPhone 浮动面板保持现有语义。
3. 接入系统导航栏并为自绘控件加入保留区布局；同步首页与导出。
4. 用纯模拟人物素材检查外屏、平展、两个半折姿态、两侧分屏、窗口缩短和大字体；验证按钮、时间轴、滑块无裁切且不跨活跃 division。
5. 播放及调参过程中折叠／展开，验证项目 ID、播放时刻、所选工具、面板开关、构图与打码参数保持；不得额外触发分析／导出。
6. 回归取消、晚到回调、项目切换、后台与删除；身份不确定时继续阻塞；预览／导出共用变换。

本轮仅完成源码审视和设计示意，未运行原生构建、模拟器交互或真机性能测试。HTML 为布局概念，不是精确设备尺寸、安全区测量或原生 Liquid Glass 截图。
