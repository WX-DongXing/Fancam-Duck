# 提交规范

提交信息使用 `类型: 简短说明`，冒号后留一个空格，说明优先使用中文，直接描述本次改动。一个提交围绕一个明确目的，避免使用「更新代码」「修改文件」等无法说明内容的标题。

| 类型 | 用途 | 示例 |
| --- | --- | --- |
| `feat` | 新增功能或首次引入项目 | `feat: 支持构图画幅切换` |
| `fix` | 修复错误 | `fix: 阻止旧导出任务覆盖当前项目` |
| `refactor` | 重构实现，保持外部行为不变 | `refactor: 统一预览与导出的构图变换` |
| `docs` | 文档或知识库变更 | `docs: 补充媒体验证指南` |
| `test` | 测试与验证用例变更 | `test: 覆盖取消导出后的状态恢复` |
| `perf` | 性能优化 | `perf: 复用跟踪阶段的帧读取缓存` |
| `chore` | 工程维护、配置或冗余文件清理 | `chore: 清理重复设计素材` |

必要时可在类型后添加范围，例如 `fix(export): 修复导出取消竞态`。复杂改动可在正文说明原因、影响和实际完成的验证；不能把历史验证结果写成本次通过。

提交前检查暂存区，确保没有私人视频、凭据、模型转换环境或构建产物；根据 [验证指南](validation.md) 完成与改动相符的检查。代码变化时同步维护相关知识库主题。

仅在用户明确要求时提交或推送；要求提交不代表授权推送，不自动改写已有提交历史。
