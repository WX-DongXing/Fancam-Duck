# 媒体处理与性能边界

## 检测与身份

模型清单为 [manifest.json](<../../Fancam Duck/Models/manifest.json>)，包含版本、权重哈希和输入输出。模型打包进应用，无运行时下载。转换脚本在 `tools/model_export`，不是正常构建的前置步骤。

`CoreMLPeopleModels` 执行 YOLO26s-pose 和 OSNet。姿态输入 640×640，应用侧 NMS；ReID 输入宽128、高256，输出512维归一化特征。`CoreMLTrackingPipeline` actor 串行协调推理与会话，当前离线分析为6Hz，处理预览默认间隔0.2秒。分析频率、UI 更新频率和输出帧率是不同概念。

`TrackTrack` 处理身份关联，`PersonIdentityGate` 防止把相似人物切成主角，`OcclusionBridge` 提供短暂遮挡预测。每个采样时刻的检测批次（包括空结果）都会缓存；预测只用于预览，未实际确认的帧记录为待确认，不作为完整轨迹保存。目标缺失或身份冲突不再中断扫描，后续重获仍要求主角外观库唯一匹配、排除旁人归属及连续两次观测一致，不能用最近位置替代身份判断。

完整扫描后一次返回所有待确认时刻，不再自动做局部重识别或回补区间重跟踪。AppModel 持有逐点确认队列；首次进入未确认时刻最多额外调用一次全帧人物检测（包括空／失败结果），往返复用结果。手动框选直接成为该时刻的 TargetSample，既不检测框内人物，也不重新启动 analyze。全部确认后校验完整轨迹、保存缓存并进入构图／运镜／打码设置。

分析缓存版本为 tracktrack6hz-review-v3，旧轨迹缓存不复用；原视频与已生成文件不删除。采样、轨迹覆盖与打码计划共用 AnalysisSampling.interval（1/6 秒）与最大合法相邻间隔。TrackTrack 保留以 0.1 秒为单位的运动模型 dt 换算，丢失步数按 1.5 秒窗口换算为 6Hz 步数。此为现有固定机位算法适配，未验证真实视频的准确率或提速幅度。

主角锚点可位于时间范围中间，分析可能分为前向和反向两段。`AnalysisFrameReader` 负责取帧，优化时要同时覆盖反向、旋转和源时间一致性。

## 坐标与裁剪

人物框使用正向显示视频的归一化坐标。触摸需要去除 aspect fit 留黑区域再转换，不能使用整个容器尺寸直接归一化。手动选择、姿态、裁剪和输出都要遵守同一坐标约定。

`CropPlan` 负责平滑运镜与用户构图组合，`CompositionEditorStage` 提供手势画布。预览和输出使用源时间的同一组变换。调整宽高比不能通过不断销毁播放器制造黑帧；布局切换也要保持播放资源与编辑状态连续。

手动构图以用户选定的缩放和位置为准，不能在处理完成后被重新计算的自动构图覆盖。边界夹取与画幅变化都要进入预览／导出一致性测试。

人物分析完成后的时间轴拖动使用 `VideoSeekCoalescer`：同一时间仅执行一个原片寻帧，后续拖动只保留最新目标，允许约 1/30 秒容差；运镜按寻帧完成后的实际源时间取缓存轨迹。拖动中不寻帧隐藏的合成播放器，松手时精确定位原片并同步一次合成预览，开始播放时再次按当前位置定位。范围手柄保留当前构图，松手后更新片段并重建合成。切换设置、退出编辑、后台和项目切换使旧回调失效；设置更新中断拖动时补一次精确原片寻帧。生成后的工作台预览也允许拖动同一时间轴：仅寻帧成片播放器，使用 `源时间 - 片段起点` 定位，范围限制在片段内；拖动暂停播放，松手精确定位，可再次点播放继续。此操作不调整起终点，也不重新识别人或生成视频。

已完成分析、但尚无完整打码计划时，设置预览从已有逐时刻人群观测和主角轨迹调用 `AutomaticRedaction.build`，在后台构建随源时间变化的遮挡轨迹；不再将打开面板时的固定人物框铺满整段视频。已有有效计划直接复用；新建的预览计划只交给原片 compositor，不写入项目、不据此开放尚未确认的动态播放。拖动时间轴只寻帧和查询轨迹，不重新运行人物模型。旧缓存缺少人群观测或分析前的停帧预览仍使用原有静态回退。


## 打码与合成

主角分析始终记录所选片段的人群检测批次，随轨迹保存；重开后恢复到管线，设置期寻帧也使用缓存观测。`AutomaticRedaction`、`RedactionTracker`、`RedactionPlan` 复用这些批次建立非主角遮挡轨迹，`RedactionCompositor` 渲染毛玻璃、马赛克或图片。沿用现有姿态／ReID 能力，不增加 Apple Vision 检测链。

遮挡区域采用局部相邻帧平滑，包含当前观测及相邻观测的半步运动范围（兼容半采样间隔的检测缓存复用），移除前后双向长期包络与固定归一化外扩，减少快速移动时过度膨胀。计划带 smoothingVersion=6，旧计划需复用人群缓存重建；输出复用也校验计划覆盖与版本，不能把旧效果当作新成片。贴片等比完整适配区域；毛玻璃使用局部区域短边决定半径，保留原片颜色，羽化在区域内部完成，采样边缘先延展原片以避免黑边。UI 整数强度 0～100 在渲染入口转换为 amount = normalizedStrength × 0.3，新上限等于旧强度 30%。毛玻璃最大半径为区域短边的 0.055 + amount × 0.125，使用 CIMaskedVariableBlur 令半径随遮罩逐渐减小，再按同一遮罩合成。人脸遮罩保持完整头部包络，归一化椭圆半径 0.8 内为完整核心，至边界逐渐归零；全身使用四边各占短边 14% 的 smoothLinearGradient 过渡。取消 22% 内缩和 1.8 次幂压缩，恢复侧脸覆盖；边界为零，区域外保持原片，中心继续移除细节。新建／缺省强度按范围区分：人脸 0.8（显示 80）、全身 0.3（显示 30）；切换范围时应用该范围默认值，同一范围内可继续手动调整。读取已保存的显式强度不覆盖，仅缺失字段时按范围补默认值。UI 与模型均允许强度为 0：毛玻璃及马赛克在 0 时直接返回原片，渲染 amount 低于 0.3 时用 amount / 0.3 缩放半径／块大小，避免刚离开零点就跳到固定最低强度；贴片忽略强度。配方版本同时用于使旧渲染成片失效。

进入导出前校验主角冲突、计划覆盖和图片有效性。图片不生成额外阴影。整人区域仍是矩形包络，细致交叠避让需要进一步能力，不能通过放大所有矩形来掩盖缺陷。

## 编码与音频

`VideoExporter.preview` 与 `exportMovingCrop` 共用合成链路。先验证轨迹完整、配置有限值、编码尺寸和画幅匹配，再创建视频合成及音频混合。音轨按相同源时间范围截取；视频顺利生成不代表音频同步已经验证。

修改旋转、裁剪、帧率或时间范围后，验证像素尺寸、时长、目标位置和音轨时间。仅对比两张 UI 截图不足以证明成片一致。

## 性能优化原则

优先检查重复解码、精确 seek、模型缓冲区分配、冗余 ReID、预览重建与主线程工作量。保持分析准确率与身份门控，不能通过跳过不确定帧获得表面提速。

合成准备只生成一次逐帧运镜轨迹；开启打码时直接交给自定义 compositor，避免重复求解及创建无用 layer ramps。主角位置查询直接对 TargetSample 二分插值，不为每次查询转换整段数组。设置预览的 detached 运镜任务使用取消处理器与外层任务联动，求解和插值合作检查取消；取消后返回空结果，由调用方的任务／项目 ID 校验或 CancellationError 阻止发布。

前后对比需固定视频、主角、时间区间、画幅、输出分辨率、硬件和运行方式。分别记录分析、打码、编码耗时及纠正次数；区分冷启动和热启动。轨迹速度／加速度指标支持运镜比较，但不能代替观看成片，也不能外推真机 ANE 吞吐。

## 手动确认与数据持久化（2026-10-21）

手动框选由固定的原片画布接收单一拖动手势；保存用户矩形，不以检测框替换。review-<UUID>.json 存储扫描样本、全部人群批次、确认点与检测已调用标记，写入使用原子文件并按版本、源摘要、所选范围和初始主角校验。返回项目可恢复黄色待确认／绿色已确认状态；失败和空检测不会因导航重试。删除项目同时删除该文件。

确认期间锁定播放与起止点，允许时间轴标记及前后待确认跳转。初始主角与 targetTime 不随逐点确认改写。确认数据按当前采样时刻写入；最后一个点确认后只校验／保存，不调用模型。任务和项目 ID 保护晚到检测；离开项目使确认任务失效，不能覆盖另一项目。已完成的分析和打码继续共用同一批缓存。
