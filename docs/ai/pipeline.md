# 媒体处理与性能边界

## 检测与身份

模型清单为 [manifest.json](<../../Fancam Duck/Models/manifest.json>)，包含版本、权重哈希和输入输出。模型打包进应用，无运行时下载。转换脚本在 `tools/model_export`，不是正常构建的前置步骤。

`CoreMLPeopleModels` 执行 YOLO26s-pose 和 OSNet。姿态输入 640×640，应用侧 NMS；ReID 输入宽128、高256，输出512维归一化特征。`CoreMLTrackingPipeline` actor 串行协调推理与会话，当前离线分析为10Hz，处理预览默认间隔0.2秒。分析频率、UI 更新频率和输出帧率是不同概念。

`TrackTrack` 处理身份关联，`PersonIdentityGate` 防止把相似人物切成主角，`OcclusionBridge` 处理短暂遮挡。超过短暂遮挡窗口仍未找到目标时，记录待回补帧并继续扫描；只有连续两帧外观唯一且一致时重获主角。扫描完整片段后，`DeferredTargetRecovery` 先用缓存检测和整段已确认的外观库重新关联，再对仍缺失的帧以两侧已确认位置估计区域进行一次局部重试。位置插值只作为检索参考，不直接写入已确认轨迹。重获与回补均保留其他人物的轨迹归属排除，局部重试使用不重复的检测 ID；临界相似候选继续参与唯一性比较。仍失败则阻塞在首个缺失帧并直接开启手动框选；手动锚点提交后复用已扫描结果继续回补。明显身份冲突仍保留原阻塞门控。当前 TrackTrack 为固定机位适配，不能声称复现论文的全部能力或指标。

分析缓存版本为 deferred-v2，旧版轨迹缓存需重新分析以采用新回补语义；原视频与已生成文件不删除。

主角锚点可位于时间范围中间，分析可能分为前向和反向两段。`AnalysisFrameReader` 负责取帧，优化时要同时覆盖反向、旋转和源时间一致性。

## 坐标与裁剪

人物框使用正向显示视频的归一化坐标。触摸需要去除 aspect fit 留黑区域再转换，不能使用整个容器尺寸直接归一化。手动选择、姿态、裁剪和输出都要遵守同一坐标约定。

`CropPlan` 负责平滑运镜与用户构图组合，`CompositionEditorStage` 提供手势画布。预览和输出使用源时间的同一组变换。调整宽高比不能通过不断销毁播放器制造黑帧；布局切换也要保持播放资源与编辑状态连续。

手动构图以用户选定的缩放和位置为准，不能在处理完成后被重新计算的自动构图覆盖。边界夹取与画幅变化都要进入预览／导出一致性测试。

## 打码与合成

主角分析始终记录所选片段的人群检测批次，随轨迹保存；重开后恢复到管线，设置期寻帧也使用缓存观测。`AutomaticRedaction`、`RedactionTracker`、`RedactionPlan` 复用这些批次建立非主角遮挡轨迹，`RedactionCompositor` 渲染毛玻璃、马赛克或图片。沿用现有姿态／ReID 能力，不增加 Apple Vision 检测链。

进入导出前校验主角冲突、计划覆盖和图片有效性。图片不生成额外阴影。整人区域仍是矩形包络，细致交叠避让需要进一步能力，不能通过放大所有矩形来掩盖缺陷。

## 编码与音频

`VideoExporter.preview` 与 `exportMovingCrop` 共用合成链路。先验证轨迹完整、配置有限值、编码尺寸和画幅匹配，再创建视频合成及音频混合。音轨按相同源时间范围截取；视频顺利生成不代表音频同步已经验证。

修改旋转、裁剪、帧率或时间范围后，验证像素尺寸、时长、目标位置和音轨时间。仅对比两张 UI 截图不足以证明成片一致。

## 性能优化原则

优先检查重复解码、精确 seek、模型缓冲区分配、冗余 ReID、预览重建与主线程工作量。保持分析准确率与身份门控，不能通过跳过不确定帧获得表面提速。

前后对比需固定视频、主角、时间区间、画幅、输出分辨率、硬件和运行方式。分别记录分析、打码、编码耗时及纠正次数；区分冷启动和热启动。轨迹速度／加速度指标支持运镜比较，但不能代替观看成片，也不能外推真机 ANE 吞吐。
