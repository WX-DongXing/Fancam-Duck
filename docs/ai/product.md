# 产品规则与交互约束

## 产品名称

中文名「直拍鸭」，英文名「Fancam Duck」，突出从群舞视频中剪出个人直拍。工程与 Scheme 使用 Fancam Duck，Swift 模块与标识符使用 FancamDuck，测试模块使用 FancamDuckTests／FancamDuckUITests。中文系统显示直拍鸭，英文系统显示 Fancam Duck。签名 Bundle ID 使用 com.fancamduck.com，测试使用 .tests／.uitests 后缀，iOS 与 Mac Catalyst 共用主标识。Bundle ID 从旧标识切换后会使用独立应用容器，旧安装的数据不会自动跨容器迁移。Application Support 默认使用 Fancam Duck；首次打开时仅在新目录不存在的情况下迁移旧 AICut 数据目录，不覆盖已有新目录。

首页手机标题、宽屏标题和 Mac 侧栏使用同一 A1 鸭子 Logo（`BrandLogo`），与系统 AppIcon 共用母图。Logo 仅用于品牌位置，功能按钮保留语义图标。

## 核心流程

导入视频 → 全览选主角与时间范围 → 分析并保存主角与人群结果 → 构图／打码即时设置 → 生成视频 → 同一工作台预览与导出。返回修改复用已有分析，再按新设置生成。

初次打开显示完整原片，通过 aspect fit 容纳不同视频比例，不能直接裁成单人画面。点击人物只完成选择，需明确点击“分析所选片段”后启动分析；首次分析前可以更换主角，分析后只在身份阻塞时重新指定同一人物。手动框选确认后直接作为用户指定的主角区域和时间锚点，不再调用区域候选识别；后续分析、身份门控、打码与生成沿用现有链路，框选本身不视为已完成跟踪。

## 编辑页

- 手机编辑页不滚动；时间截取直接集成于共同时间轴，不恢复独立的“片段”入口。
- 构图、运镜、打码在原页面展开设置区域。模式切换与生成视频同处最底部操作栏，具体设置位于其上方；保持视频为主体。
- 默认舒缓运镜；恢复独立“运镜”工具，使用原生分段控件选择舒缓／标准／灵敏，修改即时更新预览并用于导出，不重新分析人物。
- 使用玻璃材质和 SF Symbols；旧版本的暖白布局和巨大关闭按钮不是当前设计依据。
- 分析／生成时动画隐藏设置，仅在底部状态按钮显示百分比及进度背景；重新选择／取消是独立玻璃按钮，不重复放置进度卡片。
- 左上角返回默认提交当前构图与编辑设置、保存项目并直接回首页，不显示确认弹窗；真实项目与演示流程一致，后台任务沿用现有取消机制。
- 主角框使用主角语义，不显示供用户点选的候选数字列表。候选数量变化不应让页面重排。

## 统一视觉风格

整体遵循现有编辑页的玻璃设计语言。iPhone 的选人／选段、分析中、分析暂停、分析完成后的设置、生成中及成片预览／导出操作区域，应使用一致的玻璃材质、圆角、描边、间距和胶囊按钮。编辑流程使用同一个工作台的不同状态，保持视频、时间轴与页面框架稳定；状态改变时切换底部控件和功能可用性，使用短促的淡入淡出或小幅位移动画，并尊重系统减少动态效果设置。状态信息与操作按钮分开布局，按钮各自拥有独立玻璃表面，不再用大卡片同时包裹状态和按钮。不能随阶段切换成另一套实色卡片风格。构图、打码设置沿用现有控件和布局；新增流程页面复用它们的视觉规范。

原生界面优先复用现有 `StudioGlassGroup`、`glassSurface` 等玻璃组件，保持背景透出、清晰的文字对比和明确的选中／禁用状态；遵循系统减少透明度等辅助功能设置。HTML 设计稿以半透明深色材质、背景模糊、细亮描边和统一圆角模拟玻璃效果，不代表原生材质的实际渲染。设计评审时同时检查各阶段的一致性和手机编辑页不滚动的约束。

## 构图

当前标签为 `16:9`、`4:3`、`1:1`，按产品的高宽约定显示。实际宽高比分别为 9/16、3/4、1；不要擅自按常见宽高标注习惯倒置。定义见 `Fancam Duck/Domain/Project.swift` 的 `OutputAspectRatio`。

比例、构图／运镜／打码工具、打码范围和打码样式统一使用系统原生分段控件（UISegmentedControl），比例及打码面板分段控件实际高度为 48pt，iPhone 与 Mac Catalyst 共用面板控件、间距和生成按钮，底部构图／运镜／打码控件与生成按钮共用 56pt 高度，支持连续拖动选择；构图／打码保留图标和文字，打码各组选项之间至少留 8pt、底部操作按钮等宽且间隔 12pt；新比例立即更新，构图预览计算采用最新选择覆盖旧任务，不因计算忙碌将整个设置面板变暗。

支持画面拖动、双指缩放、缩小／放大、水平居中和垂直居中。单轴居中应保留另一轴及缩放。新流程设计已确认：分析完成后的设置工具提供构图／运镜／打码，不再提供选人入口；构图和打码修改即时生效并保留配置，不提供面板级取消／完成。预览和导出应共享同一份裁剪逻辑。源画面边界仍约束可移动范围。

## 打码

默认关闭打码，由用户手动开启；开启后自动处理主角以外所有人物，不要求逐人勾选，不允许把主角作为打码对象。支持人脸和整人范围，毛玻璃、马赛克、贴片一次仅生效一种。贴片仅用于人脸，默认透明背景鸭子 Logo，另提供猫咪、星星和外星人；素材 PNG 嵌入项目，预览与导出共用。切到全身时隐藏贴片，若原为贴片则切换毛玻璃。贴片不添加额外阴影或底板。人脸贴片内容使用 1.32 倍填充（原 1.12 倍），保留原遮挡边界，预览与导出一致。

iPhone 紧凑打码面板保持原 184pt 预留空间：顶行“打码”原生开关及问号说明，问号紧邻文字，点击在原位上方展开“对主角外人物进行打码”轻提示气泡，点空白收起，无确认弹窗；仅开启时显示人脸／全身范围菜单，关闭时开关靠最右边；开启时菜单宽度与间距用 0.28 秒展开，开关平滑左移到菜单前，菜单同时淡入，关闭时反向收起。减少动态效果时直接更新。中行为原生样式分段，底行直接调整强度并显示百分比，贴片样式则显示四个图片选择按钮，不显示 Logo 文字或“主角不打码”。移除手机“范围／强度”切换和重复的开启／关闭按钮；低频“回到选人帧”放在范围菜单中。关闭时仍可预设样式和强度。Mac 与宽屏保持原面板布局。

切换打码工具保持已设置的构图，只在该构图内显示遮挡，不改变画面整体亮度。遮挡效果需要时序稳定，不能直接随瞬时检测框缩放跳变。整人矩形遮挡可能影响交叠的主角边缘，不能声称已达到分割级避让。

## 处理和导出

身份不确定必须停在问题帧，重新点选并确认后才继续。纠正仅在出现异常时提供，不作为常驻设置。普通播放与时间轴拖动不能越过阻塞，明确的相邻帧检查入口可保留。

返回编辑后，若输出配方已变化需重新生成。已有跟踪可复用时不必重新做全部身份分析，但仍需更新构图／打码与输出。导出完成页将保存相册作为底部主操作，返回调整和分享为次级操作。

## 多端

依据窗口可用空间布局，不只按设备名称判断。Duo 展开时使用主次区域，折叠／旋转保持主角、时间范围和构图状态。Mac 使用桌面工作台，提供文件导入与文件保存。新流程设计中，Mac 与 iPhone 共用工作台状态、即时生效设置、问题帧确认和独立玻璃操作按钮；Mac 仅按桌面空间采用视频与设置分栏，不引入不同的确认步骤或图片选择流程。Mac 的返回、播放、构图／打码切换、比例、位置缩放和底部操作按钮均复用同一玻璃按钮语言；选中使用更亮的玻璃底与描边，禁用降低可用性对比，不混入普通实色按钮。iPhone 首页最近项目移除每行右侧更多按钮，保留侧滑删除及确认；宽屏与 Mac 保留菜单入口，不删除相册原片。

构图／运镜／打码是不可取消选中的 Tab，进入设置默认选中构图，重复点击当前项保持选中。比例、构图／打码、打码范围与样式等互斥模式切换使用一体式玻璃分段控件：共享胶囊底座与单个浮动玻璃选中滑块，切换时滑块平移；不要拆成一排独立玻璃按钮。独立动作（生成、暂停、返回等）继续使用独立玻璃按钮。HTML 是视觉模拟，原生实现复用系统及现有玻璃组件。

Mac 设置侧栏宽 360、边距 20；设置面板内边距 16、组间距 12，分段选项内容高 44。底部模式切换和生成按钮同排等高 58，避免混用 34 高按钮。打码范围与样式采用一致的 14 号文字，底栏标签为 13。手机保持紧凑布局。

生成视频时继续显示当前构图预览，不因退出构图编辑而切回原片全览；生成期间禁用构图手势，导出沿用提交时的画幅、缩放与位置。首次分析仍显示完整原片，身份阻塞仍使用问题帧确认视图。

iPhone 紧凑首页“第一次使用？”直接启动现有演示流程，不弹出文字使用指南；不再显示底部重复的“体验演示流程”入口及其演示说明文案。

首页主标题统一为“直拍快剪”，用于说明跟拍用途；最近项目列表仍使用“最近项目”。

分析／生成主按钮的百分比保持单行并优先保留完整宽度，预留 100% 的显示空间；紧凑布局缩小内边距与文字间距，避免完成瞬间折行。

分析后的构图画布覆盖整个视频预览区域，框外视频按同一变换延伸并覆盖毛玻璃，构图窗口镂空保持清晰；框内与框外均响应拖动、双指缩放。手势使用构图窗口而非扩展画布的尺寸与原点换算，不改变预览／导出裁剪。首次导入、身份纠正仍显示原片；生成期间保留构图但禁用手势。参考截图不得作为真实人物设计素材存入仓库。

编辑页顶栏（含左上角返回）层级高于构图画布，毛玻璃与扩展视频严格裁剪在视频预览区域内，不能覆盖顶栏或拦截返回手势。

分析前和分析后的设置页都允许拖动时间轴起止点；播放限制在所选区间，预览与导出按同一起止点生成音视频。已分析区间内裁短复用轨迹，扩展到未覆盖区间需重新分析；执行分析／生成及身份阻塞期间不修改正在执行的任务输入。

手动框选人物使用直角矩形轮廓，四边中点分别提供矩形手柄（上下横向、左右纵向），单边调整只改变对应轴并固定对边；可见手柄最长 18pt、最厚 3pt，长度不超过对应边长 35%，以边框为中心跨线绘制，内外各一半；点击区最大 48pt，小框时限制为对应尺寸以留出中央移动区域；框内单指拖动只移动位置，保留最小尺寸和原片边界约束，不使用四角圆形控制点。

手机分析前选择页、分析及生成进行中的顶栏标题统一为“人物分析”；分析完成后的设置页仍显示“视频工作台”，身份阻塞继续显示“需要确认人物”。

人物分析时原“暂停分析”操作改为“重新选择”：取消并作废当前分析回调，清空人物选择、轨迹、进度与旧输出引用，回到所选片段起点，必须重新点选人物才能再次分析。片段起止点和输出偏好保留。生成阶段仍为“取消生成”；应用后台的内部暂停机制保留。

自定义按钮的尺寸、内边距和 contentShape 必须属于 Button 的 label（或 ButtonStyle 的 configuration.label），确保可见背景内空白处也响应；不能只在 Button 外加 frame 扩大外观。共用文字按钮统一整块矩形热区，胶囊主操作与系统图标覆盖其完整控件区域。原生菜单、开关及分段控件沿用系统事件。

人物分析遇到缺失目标时先记录并继续扫描完整所选片段，扫描后基于已确认人物信息回补；回补失败才定位缺失帧并直接进入手动框选。短暂遮挡恢复及明确身份冲突门控保留，未解决的缺失片段不能进入构图生成或保存为完整分析。手动确认后复用已扫描结果继续处理，不重跑整段检测。

手动框确认未通过（如选区过小、打码冲突）时保留草稿和框选界面，显示原因；只有接纳成功才退出框选。

首页提供「设置」入口：手机品牌行右侧、宽屏首页右上角、Mac 侧栏底部。设置仅包含「关于直拍鸭」和「评价」，沿用玻璃材质、整行点击及原生导航；关于页展示 Logo、中英文名称、实际版本与构建号、产品简介，并提供开源仓库及 AGPL-3.0-only 协议链接；两行均可整行点击，在系统浏览器打开对应 GitHub 页面。评价调用系统 StoreKit 评分请求，是否显示由系统决定，不使用虚构的 App Store 链接。
