# Fancam Duck 产品与技术方案

版本：首版设计基线 1.10  
日期：2026年10月17日  
状态：技术主线确定，可进入原型设计；具体模型配置经真机验证后冻结

Fancam Duck 将多人舞蹈视频转换为持续跟随指定舞者的竖屏视频。首版围绕导入、自动确定人物时间范围、选人和构图设置、自动跟踪与运镜、预览纠正及导出形成闭环。

算法基线固定为 YOLO26s-pose、TrackTrack 和 OSNet x0.25。采用本机分析与导出，不依赖云端服务。人物身份准确性和运镜观感分别验收，模型版本在验证通过后冻结。

当前优先保证识别、身份连续性、运镜和完整任务性能，不因授权费用讨论反复更换技术路线。保留YOLO26s-pose作为主模型，OSNet x0.25作为轻量ReID基线；仅在样片或真机数据表明瓶颈时，对单个组件进行有针对性的替换。这是当前工程选型，不代表已证明其优于所有组合。商业授权与分发兼容性作为发布前必须关闭的准入项。

媒体执行策略为保留原片、解码后按模型输入缩放；代理视频仅在长视频或反复预览有明确收益时生成。最终导出与局部精检读取原片。先搜索首尾人物边界，再对选定片段顺序分析，避免全源预扫描与全量二次解码成为默认路径。

## 产品目标与范围

### 核心体验

用户导入视频后，系统自动建议有人物出现的时间范围。用户点击舞者，在同一阶段设置输出分辨率、人物占比和跟随偏好。系统生成平滑的竖屏构图，标记不确定区间；用户纠正后导出带原音的视频。

优先级依次为：避免错误锁定其他人、保留完整舞蹈动作、镜头运动自然、降低人工纠正次数、缩短处理时间。需要结合正确跟踪覆盖率检查第一项，不能靠频繁拒绝判断降低错误率。

### 首版范围

| 项目 | 设计约定 |
| --- | --- |
| 视频内容 | 单条连续镜头，优先验证2至10名舞者 |
| 来源 | 系统相册与文件选择器；iCloud素材先下载到本地 |
| 常见输入 | MP4、MOV中的H.264或HEVC；以系统可解码能力和实际兼容性测试为准 |
| 输入方向和帧率 | 横屏、竖屏、旋转元数据；30或60 fps及可变帧率 |
| 输出画幅 | 仅保留16:9、4:3、1:1，不额外标注宽高；16:9实际为宽9高16，4:3实际为宽3高4，预览与导出共用所选比例 |
| 输出分辨率 | 按源视频和所选画幅的可用裁剪尺寸提供，从小到大排列，不默认放大；切换比例尽量保留原画质档位 |
| 输出编码 | MP4、H.264视频、AAC音频，默认30 fps |
| 构图 | 自动取景为全身留白；手动构图保持确定的缩放与位置，不再自动拉远；支持水平和垂直分别居中 |
| 编辑 | 一段源视频、一个指定舞者、身份纠正和构图关键帧 |
| 项目 | 自动保存，可重新打开和继续编辑 |
| 暂缓 | 多片段拼接、音乐编辑、滤镜、多人自动切换、云端增强、整段全局轨迹优化 |

HDR输入首版统一转换为SDR，需要验证亮度与色彩。输出1080p不代表能够恢复低分辨率源视频的细节。检测到切镜时创建问题标记，首版不自动跨镜头恢复身份。

## 用户流程与页面

主流程：导入相册视频 → 视频编辑工作台（首帧选人、时间范围、设置、处理进度与纠正共用同页）→ 导出。点选舞者后在页面中确定，再原位处理，处理结束在原工作台检查与纠正，不切换选人页或预览页。

时间范围扫描与设置页面可以并行，但必须标明范围是初步建议还是已完成边界确认的结果。

### 项目入口

提供导入入口与本地项目列表，首页预留操作指引视频。点击主导入按钮直接调用系统相册视频选择器，不先显示导入方式面板；文件导入作为次级入口在后续交互中另行安排。项目显示缩略图、编辑时间和状态。首次使用不要求账号。

最近项目左滑显示删除按钮，点击后先确认，再移除项目与编辑记录；取消时保留。删除确认明确导入副本及缓存的清理范围，不删除相册原片，也不删除用户已保存或导出的成片。无项目时显示空状态与导入引导。提供项目操作菜单作为无法滑动时的等效入口。

### 视频编辑工作台：选人与时间范围

相册选择后直接显示视频第一帧并检测人物，在画面上提供可点击的人物框，不再经过独立的时间范围确认页和“下一步选择舞者”。直接点击画面中的人物框，只高亮目标并进入待确定状态，不触发分析。页面内显示“确定舞者并开始处理”；未选人时禁用。用户可更换目标、调整参数后确定，随后建立身份锚点并原位分析。多人点击不明确或手动框选识别时先确认具体候选。

时间范围整合为类似iOS相册视频编辑的一条缩略帧带，左右拖柄分别调整起点和终点，播放头定位画面，显示起终时间和选中时长；不再使用两条独立滑杆。支持键盘微调和最短片段长度约束。自动范围与人工覆盖规则保留，边界确认未完成时不宣称最终范围。用户先选人时，边界确认并入分析阶段。

首帧无人或目标漏检时，不自动选择其他人；允许移动播放头到清晰帧，或手动框选后重新识别。人物锚点可位于截取范围之外，用于向选定片段传递身份，但不改变导出范围。

### 工作台内嵌设置

视频是工作台主体，直接点击视频中的人物进行选择，不提供独立选人按钮。视频下方依次为确定操作、播放与裁剪时间轴、内嵌设置/纠正工具区。设置默认展示，点击工具标签只替换同页区域；不使用弹窗、遮罩或悬浮面板，不设关闭/收起按钮。参数改变即时更新画面。处理后切换到原片直接换人，再点击确定重新处理；待确定时禁用导出。重叠人物点击不明确时在同页确认候选。

没有检测框或目标漏检时，提供“手动框选人物”。用户在暂停的原视频上拖动并调整矩形，尽量包含目标完整可见身体，确认后执行局部重新识别；该入口与预览纠正共用同一流程。

| 设置 | 默认行为 | 修改影响 |
| --- | --- | --- |
| 目标人物 | 用户点击指定 | 重新计算目标身份和构图 |
| 时间范围 | 自动建议，可调整 | 复用已有检测，补算缺失范围 |
| 分辨率 | 按源视频和所选画幅动态选择 | 影响渲染与编码，不改变构图 |
| 人物大小 | 期望人物高度约占画面75%，样片评审后调优 | 重新计算构图 |
| 人物位置 | 水平居中、垂直居中独立操作 | 只调整指定轴，保留另一轴和缩放 |
| 跟随速度 | 标准，可调舒缓至灵敏 | 重新计算运镜 |
| 全身保护 | 默认开启 | 允许降低实际人物占比以容纳动作 |

分辨率依据旋转校正后的源视频显示尺寸及9:16最大可用裁剪区域生成，取偶数编码尺寸；预设从小到大排列，末尾可提供原生裁剪尺寸。横屏1920×1080的最大可用竖屏约606×1078，因此不默认提供1080×1920档位；4K横屏可提供1080×1920。人物放大造成的额外采样损失单独提示，输出尺寸不代表真实细节。原型使用1920×1080元数据示例，未读取真实相册视频。

人物占比是可见人体高度相对输出画面高度的期望值，采用可信人体尺度并在时间上稳定。遮挡、弯腰时不直接追随瞬时缩小的人体框。默认提供一个人物大小滑杆即可，不必同时暴露多个相近参数。

选人画面可以位于片段中间。目标在片段开头或结尾尚未出现时，相应区间保持稳定构图并标记；首版默认截取范围依然依据任意人物出现时间，不偷偷改成目标人物的可见范围。

设置以实时构图示意帮助理解，自动分析完成前不将单帧预览包装为实际跟踪结果。工具区始终位于同页，点选舞者后需明确确定才进入处理；参数在预览阶段仍可修改。

### 工作台内处理状态

分别显示人物扫描、目标跟踪和生成运镜的实际阶段。优先使用已完成时间范围除以任务时间范围表示进度，不使用不可靠的固定倒计时。选人锚点位于中间时，前后两个方向的完成范围合并计算。

处理进度直接显示在原编辑工作台：开始后动画收起设置面板和选人／构图工具，保留原片、实时目标框与只读时间轴。原底部主按钮扩展为通栏，左侧显示「处理中」及暂停图标，右侧显示实际百分比，不使用独立大圆环。点按整个按钮可暂停，暂停后显示「已暂停」及原百分比，再次点按继续；身份不确定仍阻塞并在原位重新选人。动画只关联处理状态切换，不随每次百分比更新驱动整个页面重排；减少动态效果时取消过渡动画。

支持取消并保留已完成检查点。切到后台时保存状态，使用系统允许的时间尽量收尾；不承诺在后台持续完成长时间推理。重新回到前台可继续。

### 工作台内预览与纠正

主视图播放竖屏结果，可展开原视频并显示目标框、裁剪框。时间轴显示身份待确认、丢失和切镜等区间，支持跳转上一处或下一处问题。

身份纠正和构图纠正采用独立入口。重新选人会建立身份锚点；拖动位置、双指缩放会建立构图关键帧。提供撤销、重做与删除关键帧。清楚显示重算进度，避免旧预览被误认为最新结果。

目标没有被检测到时，用户选择“手动框选人物”，切换至暂停的原视频画面后框选目标。矩形表示待识别人物区域，不能与竖屏裁剪框混用。识别成功后展示候选人物与新构图，用户确认目标，再重算受影响区间；仍失败时保留框选结果，允许调整框、切换邻近清晰帧重试，或转为人工构图。

### 导出

导出前显示输出规格、预计空间需求和未确认问题数量。存在问题允许返回处理，也允许用户明确继续导出，不强制纠正所有标记。导出成功后提供系统分享与保存相册；相册权限拒绝时仍可保存至文件或分享。

## 自动时间范围

### 边界定义

默认起点是任意人物首次被可靠检测到的源视频帧，终点是最后一次可靠检测到的人物帧的结束时间。内部使用左闭右开区间，终点包含最后一帧的显示时长。音频不决定边界，中途无人不自动切段。

自动边界代表检测结果，不是现实中人物存在的绝对保证。小人物、静态海报、屏幕中的人物和极暗画面均需要在样片中验证；首版允许人工覆盖，不增加海报过滤专用模型。

### 扫描策略

快速粗扫描用于尽早给出范围建议；最终边界分别从源视频开头和结尾搜索。开头顺序检查至首个可靠人物事件，结尾按可解码小块反向搜索至最后人物事件。块内按源帧复核，确保边界之外更早或更晚的区间已覆盖，确认后即可停止该方向，无须为找边界分析整个中间部分。仅在粗扫候选边界附近精检，无法排除边缘未覆盖区间的短暂人物出现。

边界搜索使用YOLO26s-pose并缓存有效观测，正反搜索共享已检查区间。全程无人或片头片尾长时间无人仍可能需要检查整个源视频，单独作为最坏情况。目标跟踪限制在用户选段内；首轮按源帧建立精度基线，通过验证后再评估稳定区间降采样。60 fps、4K和尾部反向读取单独报告成本。

用户尚未修改范围时，扫描结束可以更新默认值；用户一旦手动修改，后续扫描只提供新的建议，不覆盖人工选择。孤立检测进入边界复核，查看邻近源帧与检测质量；不简单删除所有短暂人物出现。

| 情况 | 处理 |
| --- | --- |
| 全程有人 | 选中整段 |
| 全程没有可靠检测 | 保留整段，提示手动选择时间与人物 |
| 中途暂时无人 | 保留时间间隙，交给身份状态管理 |
| 人物始终检测失败 | 允许手动画目标区域并重试；仍失败时提供人工构图导出 |
| 用户取消扫描 | 保留建议状态与已完成范围，之后可恢复 |

## 算法架构与模型

| 组件 | 首版基线 | 职责 |
| --- | --- | --- |
| 检测和姿态 | YOLO26s-pose，640×640，Core ML FP16 | 输出全画面人物框、分数与17点姿态 |
| 轨迹关联 | TrackTrack，固定参考版本 | 轨迹关联、初始化和生命周期 |
| 外观特征 | OSNet x0.25，输入高256宽128，Core ML FP16 | 为目标及冲突候选生成归一化外观向量 |
| 身份管理 | 应用层约束 | 将用户目标与临时轨迹绑定，管理不确定性 |
| 运镜规划 | 独立模块 | 将目标范围转换为平滑9:16裁剪轨迹 |

OSNet使用人物ReID训练权重，记录训练来源和部署预处理。模型体积、参数量或公开桌面测速不代替真机结果。若基线失败，只替换有明确瓶颈的模块。YOLO26n-pose和其他ReID模型保留为后续对照，不同时进入首版主链路。

固定权重哈希、模型导出工具、模型输出形式、跟踪实现版本和参数集。YOLO26免NMS输出是否保留足够遮挡候选需要专项验证。iOS只部署Core ML模型和必要关联逻辑，参考Python实现用于行为对照。

## 核心数据流程

1. 导入媒体，读取轨道、方向、时长和编码信息，建立本地可访问来源。
2. 快速扫描建议时间范围，首尾搜索确认边界；缓存已获得的人物观测，不默认完整预分析中间全部内容。
3. 用户选人，创建固定目标身份和初始外观锚点。
4. 在选段内顺序解码，复用有效观测或执行Pose；原帧仍可用时完成TrackTrack所需的外观提取与关联，随后释放像素。已释放帧的补充需求按区间合并重读。
5. 身份规则在目标关联正式提交前确认或否决候选，写入可靠目标样本或不确定状态。
6. 用户在中间选人时，向后和向前分别分析；倒序任务使用递增的分析时钟，结果映射回源时间并排序，不直接把负时间差传给运动模型。
7. 构图规划读取目标样本与人工锚点，生成理想取景与身体保护约束。
8. 运镜模块平滑位置和缩放，完成边界约束与全身保护复核。
9. 预览读取同一份裁剪轨迹；用户修改后只重算受影响结果。
10. 导出从源媒体按时间读取画面，应用共享渲染逻辑并合成原音。

边界搜索、选段分析、按需二次解码、ReID和关联都计入用户等待时间。缓存人物观测不等于后续无须解码；OSNet需要原始像素，二次解码作为有界补充而非默认全量第二遍。密集请求顺序合并处理，避免逐帧随机寻址。中间选人采用有界小块或必要特征缓存支持倒序任务，不缓存整段原始帧。

## 模块与接口约定

接口以下列输入输出约定为准，具体语言类型在实施阶段确定。

| 模块 | 输入 | 输出 | 责任边界 |
| --- | --- | --- | --- |
| 媒体准备 | 相册或文件来源 | 媒体描述、本地来源、可处理状态 | 下载、读取轨道、方向与格式验证 |
| 时间范围扫描 | 媒体描述、扫描策略 | 建议区间、确认状态、人物观测缓存 | 区分粗扫与首尾边界确认，尊重人工范围，复用覆盖区间 |
| 帧读取 | 源时间区间、采样需求、读取方向 | 带时间戳的像素缓冲 | 有界缓冲、顺序读取和分块倒序 |
| Pose适配 | 像素缓冲、方向、可选局部区域 | 人物观测列表 | 全图或局部推理、缩放补边、输出解释、坐标还原 |
| 手动框选恢复 | 源时间、原视频归一化矩形、用户目标 | 局部人物候选、归一化观测、外观样本、恢复状态 | 重新识别、候选确认、建立人工身份锚点并触发区间重算 |
| ReID适配 | 原帧、人物区域、质量要求 | 外观向量或不可用原因 | 人物裁切和归一化，不自行判身份 |
| 跟踪身份协调 | 观测、外观、历史状态、身份锚点 | 轨迹、目标样本、问题区间 | 统一关联与身份约束，避免两套匹配冲突 |
| 构图规划 | 目标样本、画幅、人物占比、构图锚点 | 理想构图及保护约束 | 不重新检测人物 |
| 运镜规划 | 理想构图、保护约束、跟随参数 | 可按时间查询的裁剪轨迹 | 平滑、限速、边界约束和可行性处理 |
| 渲染 | 源帧、裁剪轨迹、时间映射 | 竖屏输出帧 | 裁剪、缩放、补背景、色彩转换 |
| 导出 | 媒体、渲染计划、输出规格 | 成片、进度、错误 | 视频编码、音轨、同步与文件完成状态 |
| 项目存储 | 各阶段结果及参数版本 | 可恢复项目、缓存有效性 | 检查点、撤销、资源清理 |

所有长任务暴露阶段、已处理源时间范围、取消、恢复和可重试错误。核心数据模块不依赖界面，界面不直接修改跟踪器内部状态。

| --- | --- |
| 媒体描述 | 来源标识、尺寸、方向、轨道时间、音轨、颜色信息、本地可用状态 |
| 项目配置 | 人工范围、自动范围状态、目标、分辨率、人物占比、跟随参数 |
| 人物观测 | 源时间戳、帧内编号、人体框、关键点、分数、质量信息 |
| 外观样本 | 观测引用、向量、质量、模型版本、是否为人工锚点 |
| 临时轨迹 | trackID、观测序列、运动状态、生命周期 |
| 目标身份 | targetID、绑定轨迹、固定初始特征、可靠特征库、状态 |
| 目标样本 | 源时间、人体范围、位置、观测或预测标志、身份可靠度 |
| 纠正锚点 | 源时间、人物引用或构图约束、人工优先级；框选时另存原视频归一化矩形、候选确认状态和局部坐标变换 |
| 问题区间 | 起终点、原因、是否经人工确认 |

统一采用正向显示原视频坐标，左上角为原点，持久化位置使用归一化值。模型坐标、播放器黑边和触摸坐标在适配层转换。时间使用有理数媒体时间，保留源时间到编辑时间的映射，不用浮点秒累计帧数。

像素缓冲按队列上限复用；持久化元数据和必要缩略图，不保存整段未压缩帧。缓存按源媒体、模型、预处理和参数版本分层失效。项目恢复重放检查点之前一小段上下文，避免只恢复位置却丢失跟踪历史。

## 跟踪与人物身份

### 临时轨迹与目标身份

trackID属于跟踪器，可能中断或切换。targetID属于用户选择，在整个项目中稳定。身份层允许目标在遮挡恢复后绑定新的trackID。相同trackID也必须在冲突时重新检查。

### 匹配与提交

正常区间优先使用连续运动关联，低频校验目标外观。人物靠近、运动突变、检测不稳定或竞争候选接近时，调用ReID比较相关候选。匹配同时考虑位置连续性、历史外观、候选差距和其他舞者的排他约束。姿态辅助运动与可见性，不把同步动作当作强身份证据。

身份规则必须在目标关联正式提交前执行。否决后保留最后可靠状态，并按同一套关联规则处理其他候选，不能只在错误更新后标记界面。接受条件需要绝对匹配门槛、最佳与次佳候选差距及连续时间确认，阈值由独立验证集标定。

### 外观库

保留不可自动覆盖的初始锚点，以及约8至16个有差异的可靠特征样本作为初始配置。清晰、分离、足够大且身份确定时更新。重叠、模糊、严重截断、检测异常或身份待确认时冻结。固定样本与近期样本共同用于比较，避免随错误逐渐漂移。

### 状态

| 状态 | 身份动作 | 输出给运镜 |
| --- | --- | --- |
| 已确认 | 正常关联，质量合格可更新特征 | 可靠位置与身体范围 |
| 待确认 | 冻结特征，比较竞争候选，可查看随后短时间画面 | 最后可靠范围与不确定标志 |
| 暂时丢失 | 短期预测，扩大合理搜索范围 | 预测位置、递减可靠度 |
| 需要纠正 | 不再自动提交不可靠身份，等待人工或更充分证据 | 稳定构图及问题区间 |

完全遮挡后恢复不能要求候选与预测框必须重叠，但须提高身份确认要求。位置预测不会无限向前推。相同服装、完全遮挡和位置交换造成不可判定时，保留问题标记。

### 人工纠正

重新点击人物创建强身份锚点。优先重算相邻人工锚点之间的身份区间，再更新对应构图；没有后续锚点时计算到片段末尾。相邻锚点冲突时提示用户检查，不静默覆盖。构图修改不改变人物身份。

### 手动框选后的重新识别与归一化

首版将“归一”定义为坐标统一与外观向量归一化，不改变原视频中的人物比例。手动框选是识别提示，不直接视为模型已检测到人物，也不保证后续可以持续跟踪。

1. 用户在原视频暂停帧上框选目标，将触摸矩形去除播放器黑边与显示缩放，映射为正向原视频的归一化矩形。框选支持撤销、重画、拖动及边角调整。
2. 从原始分辨率解码该帧，以框选区域为中心适当扩展上下文并限制在源图内。局部图像使用既定640×640输入执行YOLO26s-pose，保留缩放和补边变换。局部取景能减少全图缩小导致的人物细节损失，但不能恢复源图缺失的细节。
3. 将局部人体框和关键点依次映射回原视频像素坐标，再归一化到原视频宽高；关键点有效性与置信度保留，不把局部归一化坐标直接混入全图轨迹。
4. 多人候选结合框选区域的位置与覆盖关系呈现给用户确认，不自动锁定最高分人物。确认后从原始帧裁取对应人物，按OSNet规定预处理提取特征并执行L2归一化；特征质量不足时标为不可用，不伪造零向量或可靠身份分数。
5. 建立带来源信息的人工身份锚点。保留可信旧特征与其他人工锚点，冻结冲突样本，重算相邻人工锚点约束的身份区间及对应运镜。局部观测保留来源，合并到该帧观测时去重，避免为同一人创建重复轨迹。
6. 重算期间优先复用全图观测；若连续漏检，可围绕最近可靠目标位置做有预算的局部重检，同时保留全图观测帮助处理竞争人物。为局部重检设置最大连续窗口和调用预算，记录额外耗时；局部搜索不无限扩大或无限追踪，超出预算或仍失败后回到丢失状态并标记。
7. 局部重检仍没有可靠人物观测时，允许继续调整框或换帧。用户可确认一个人工位置锚点用于构图，但不将其伪装为检测结果、有效骨骼或持续跟踪成功；TrackTrack无法仅凭一个手画矩形在后续无检测帧中可靠跟随。人工构图作为可导出的降级路径。

界面依次呈现框选、局部识别中、候选待确认、区间重算、成功或仍未识别等状态。局部识别不得擅自修改人工截取范围。验证需覆盖小人物漏检、多人同框、边缘人物、旋转视频、播放器黑边、仍无检测、外观不可用以及局部重检耗时；检查所有坐标映射和特征处理一致性。

## 虚拟摄影机与运镜

运镜是首版核心质量模块。输入轨迹准确并不代表镜头自然，必须独立评审和测量。

### 构图目标

以躯干或髋部附近作为稳定中心，可信人体框和关键点确定动作保护范围。17点没有指尖和脚尖，按身体尺度及局部动作预留余量。部分关键点缺失时参考近期可靠身体尺度，不立即缩小。

人物占比决定自动初始取景大小，默认提前为伸展、跳跃留空间。用户手动构图后，以选定取景为准，不因全身保护强行拉远；仅限制在原片边界及目标中心可见范围内。画幅可选9:16、16:9、4:3、1:1，预览与导出共用裁剪路径。水平和垂直居中分别以当前参考帧舞者中心为目标，保留另一轴位置及缩放。构图面板不再显示「全身优先」开关。

### 平滑策略

首版采用可控的窗口规划与约束平滑，不引入复杂学习式摄影模型：先稳健估计中心和保护范围，再分别规划位置和缩放，限制速度、加速度及加速度变化，最后检查动作保护和源画面边界。

| 情况 | 行为 |
| --- | --- |
| 小幅身体摆动 | 中心缓冲区内不频繁移动镜头 |
| 持续位移 | 利用前瞻平滑起步和跟随 |
| 突然反向 | 平滑减速后反向，必要时暂时拉远 |
| 跳跃或伸手 | 提前拉远保护身体 |
| 动作范围短暂缩小 | 保持原尺度，缓慢拉近 |
| 遮挡 | 延续可靠尺度，预测后逐渐减速 |
| 恢复锁定 | 平滑衔接，身份不确定期间不盲目追候选 |
| 到达源画面边缘 | 限制取景位置，必要时补背景 |
| 人工关键帧 | 精确满足明确约束，邻近区间平滑过渡 |

拉远速度可以快于拉近速度，减少身体被裁掉和频繁呼吸式缩放。平滑后再次检查身体包含情况；仅对结果做硬边界截断可能重新引入抖动，需要回到相邻窗口修正。跟随速度控制允许镜头响应，不直接改人物跟踪结果。

人体在源视频中已被切掉时无法恢复。人体占比、全身保护和用户指定缩放冲突时，界面明确提示；人工紧构图允许保留，但不再显示全身保护承诺。

### 运镜验收

分别记录人物出框、新增身体截断、中心偏差、高频位置变化、缩放变化、边界突跳和遮挡恢复突跳。按输出坐标和实际时间归一化，避免不同分辨率或采样率产生不可比数字。

舒适度由实际播放评审确定，至少检查正常速度下的起步、停步、反向、跳跃、伸展和遮挡。数值平滑不代表观感合格，平滑过度导致滞后也判为问题。

## 预览与导出

预览和导出共用裁剪轨迹、时间映射与渲染规则。低清预览可以降低像素尺寸，不能改变取景和时间。预览可缓存短段，但轨迹版本变化时必须失效。

导出按源时间采样并映射到固定30 fps，所有轨道使用同一截取起点和时间偏移，处理原轨道起始差异及可变帧率。保留原音含义是保留声音内容，默认AAC重编码，不承诺音频字节不变。没有音轨也正常导出。

使用AVFoundation进行媒体读写和音轨合成，Core Image在GPU上完成裁剪、缩放、背景和色彩处理；仅在性能证据需要时增加自定义Metal。复用像素缓冲并限制并发。导出取消或失败不将不完整文件显示为成功结果。

## 性能和准确性验证

### 设备与素材

初始设备矩阵为iPhone 13搭载A15和iPhone 15 Pro搭载A17 Pro；最低支持机型在验证后确定。Release构建、固定模型与系统版本，每个用例至少重复三次，区分冷启动、预热和持续负载。

先建立30段真实舞蹈样片，按原始拍摄视频或场次拆分调参与固定测试集。困难区间逐帧标注目标身份、可见性和身体保护范围。覆盖同服装、交叉、遮挡、远景、暗光、模糊、转身、地面动作及移动机位。扩大验证时加入DanceTrack和更多真实素材。

### 验证顺序

1. 转换一致性：同一图像及人物裁块对比原模型与Core ML的框、关键点、外观距离和候选排序。
2. 移植一致性：固定观测与外观输入，比较参考跟踪器和iOS的关联、生命周期与目标绑定。
3. 边界准确性：人工标注首末人物帧，统计时间误差、漏掉短暂出现和误收空白时间。
4. 身份准确性：统计错误锁定、覆盖、切换、遮挡恢复和人工纠正。
5. 构图与运镜：统计截断并实际播放评审。
6. 单模块性能：加载、推理P50/P95、预后处理、执行设备、内存。
7. 全流程性能：导入本地后扫描、二次解码、ReID、关联、落盘、运镜、预览就绪及导出分别计时。
8. 持续负载和异常：连续10分钟、后台中断、取消、空间不足、项目恢复、源文件不可用。

### 首轮准确性目标

| 指标 | 目标定义 |
| --- | --- |
| 正确跟踪覆盖率 | 可判定可见时间中正确跟随至少98%，待确认计为未覆盖 |
| 错误锁定占比 | 锁定其他人的时间不超过可判定可见时间的0.5% |
| 身份切换 | 不超过每目标分钟0.1次，并报告单次错误持续时间 |
| 遮挡恢复 | 重新可见且身份可判定的事件，1秒内正确恢复至少95% |
| 新增身体截断 | 源画面身体完整且输出策略可容纳时，不超过适用帧的1% |
| 人工纠正 | 中位数每分钟不超过1次，同时报告P90和零纠正视频占比 |

以上为工程目标，需在验证后确认可达性。不可判定事件单独报告比例；按场景报告样本量，不能只报总体平均。自动首末帧误差在第一轮测试建立分布后设门槛，不能以逐帧执行代替实际识别准确性。

### 首轮性能目标

| A15测试项 | 初始目标 |
| --- | --- |
| 60秒1080p30普通素材至预览就绪 | P50不超过60秒，P95不超过90秒 |
| 60秒困难素材至预览就绪 | P95不超过180秒 |

至预览就绪从本地素材可读且用户已提供必要设置开始，包含所有扫描和解码工作；若设置前已做扫描，额外报告扫描总耗时和用户点击开始后的剩余等待，不能隐去预计算成本。网络下载单列。4K及60 fps独立报告。

先建立选段逐源帧结果，再验证稳定区间15 Hz关联、风险区间加密的优化。首尾边界之外需确认的区间仍按源帧检查。实际时间差参与运动预测；30和60 fps、正向和倒序任务均验证。准确性与速度使用同一套参数验收。

| 阶段 | 交付 | 通过条件 |

| 媒体闭环 | 导入、时间轴、固定竖屏预览和原音导出 | 方向、裁剪范围、色彩、音画同步正确 |

原型可先于算法实测进行，但不得在原型中承诺未经验证的处理时长或全自动准确率。完整产品开发前，模型转换和身份验证是技术准入门槛。

## 原型设计交付要求

需要覆盖四个主要界面：项目入口、统一视频编辑工作台、导出设置、导出结果。工作台包含选人、裁剪、内嵌设置、原位处理进度、预览与纠正状态，禁止拆成独立选人页、设置页或纠正页。

原型至少演示以下场景：正常成功、初步范围更新为确认范围、人工范围不被扫描覆盖、中间帧选人、交叉后恢复、需要重新选人、漏检后手动框选并局部识别成功、多候选确认、框选后仍失败及换帧重试、构图关键帧修正、全身补边、取消恢复、无人物、导出失败及相册权限拒绝。

主界面使用产品语言表达状态，不向普通用户暴露模型名、轨迹ID或ReID阈值。技术调试叠层单独保留，便于开发测量。

功能闭环、模块输入输出、缓存边界和人工纠正方式已明确，可以进入原型设计。复核后修正了以下潜在冲突：

| 潜在冲突 | 处理决定 |
| --- | --- |
| 抽帧扫描与第一最后人物帧要求冲突 | 快扫提供建议，从两端按源帧确认边界，避免无必要扫描中间全部内容 |
| 扫描结束覆盖用户修改 | 人工范围优先，后续只提供建议 |
| 只分析截取段导致自动边界无法确定 | 扫描覆盖源视频；选定范围限制目标跟踪和导出 |
| 默认范围包含非目标人物 | 保留任意人物边界，目标缺席区间标记，不偷偷改范围 |
| 中间选人与顺序跟踪冲突 | 正反两个任务，独立分析时钟，源时间映射 |
| 检测缓存被误认为免二次解码 | ReID按需读取原帧，计入性能和队列设计 |
| 平滑与全身保护冲突 | 前瞻构图、快速拉远、缓慢拉近、结果复核 |
| 输出分辨率与人物比例混淆 | 分辨率控制像素，人物比例控制取景 |
| trackID与用户身份混淆 | targetID独立，身份约束在提交前执行 |
| 全身保护与紧构图冲突 | 默认保护，人工紧构图明确提示 |
| 原型承诺与未测算法性能冲突 | 原型表达状态和进度，性能作为验证门槛 |

仍需通过实际验证关闭的技术风险为：YOLO26s-pose与OSNet的Core ML输出一致性、相同服装遮挡后的身份区分、首尾搜索和补充解码成本、运镜主观观感。它们不阻碍原型设计，但影响最终模型和性能承诺。

### 纠正入口显示规则（最新交互约定）

正常导入、选人及跟踪状态不显示纠正操作，也不使用禁用按钮占位。只有分析实际产生目标漏检、目标丢失或身份匹配不确定事件时，才在同页显示带时间点和原因的异常入口及纠正工具；构图设置保持独立于异常状态。处理中可先继续分析，用户点击异常时定位相应画面并暂停处理，避免边纠正边变更结果。确认目标正确或重新识别恢复后清除对应异常；全部异常解决后隐藏纠正工具并返回设置区域，暂停的处理继续。单纯保存构图关键帧不清除身份异常。初次选人漏检时仍保留手动框选入口。

原型在演示进度达到56%时模拟22.4秒的身份匹配异常，用于评审入口出现、定位和消失；这不是实际模型检测结果，真实实现须由异常事件驱动。


### 确认处理与自动进入导出（最新流程）

编辑阶段底部主操作统一为“确认并开始处理”，未选人时禁用。画面中的人物选择只高亮，视频下方不重复放置确认按钮；用户完成时间范围与参数设置后在页底确认。处理完成且没有未解决的识别异常时自动进入导出页，编辑页不再提供“导出视频”按钮，也不增加中间完成确认。实际编码仍需在导出页点击“开始导出”。

发现漏检、丢失或身份不确定时暂停处理，页底改为“定位异常并纠正”；解决后继续原处理任务，全部完成后自动进入导出页。原型模拟56%进度的身份异常；确认原目标、点选正确人物后确定、或手动框选识别确认均可继续。存在未解决异常时不能通过“继续处理”跳过。自动进入导出只属于本次确认发起的处理任务，打开已有项目不会自行跳转。


### 识别异常必须阻塞（最新规则，覆盖之前可仅确认原目标的说明）

一旦处理发现目标漏检、目标丢失或身份匹配失败，立即停止进度推进，保存检查点，定位异常画面，自动显示同页人物纠正区。旧目标不作为已确认候选沿用，用户必须重新点击画面人物，或手动框选并完成候选识别确认。未选择时底部显示禁用的“选择人物后才能继续”；明确选择后变为“确认目标并继续处理”。不提供“确认原人物正确”或跳过异常的捷径。

仅选择不自动继续，确认后才清除本次异常并从检查点继续；新的异常再次阻塞。异常存在时即使暂停标记被改变也不得推进，不允许进入导出页。构图修改、播放、退出框选均不解除阻塞。处理完成后自动进入导出页。


### 相机式单屏编辑（最新布局，替代下方内嵌设置区）

编辑页禁止纵向滚动。可用高度按顶部安全区、导航、视频主体、紧凑时间轴和底部确认操作划分，视频区域弹性适配高度。取消设置列表和编辑工具标签；分辨率、全身保护浮在画面顶部，人物大小、跟随速度、水平位置及手动框选浮在画面底部。轻点参数后仅在视频内显示对应的一行滑杆或选项，再次点击收起，不创建弹窗或遮罩；选项仍从小到大。底部设置不挤占时间轴及确认按钮。

首帧人物直接点选，页底确认处理。识别异常阻塞、提示与候选确认也占用原视频内的控制区域；手动框选使用视频底部短提示和默认框/换帧/退出操作，页底主按钮依状态变为识别或确认候选，无新增纵向区域。处理成功自动进入导出。原型单屏布局使用可视高度约束；自动浏览器验证仍受本地页面策略限制，真实iPhone安全区、横竖屏及动态字体适配须在应用阶段验证。


### 处理中的动态目标框

处理时视频画面随分析时间推进，持续绘制选中舞者的目标框和“正在跟随·舞者N”标签。目标框跟随当前人物位置与动作范围更新，与9:16取景框区分；不会显示全体人物选择框。用户暂停后冻结当前画面与目标框。身份匹配异常时隐藏可信跟踪框，定位问题画面并展示重新选人框，阻塞等待确认；恢复处理后继续显示新目标框。该覆盖层只用于编辑预览，不烧录到导出成片。当前为示意人物动画驱动，不代表真实模型追踪结果或处理速度。

### 构图锚点落地修正（2026-10-18）

用户完成构图时，保存参考源时间与实际可见裁剪矩形（分别按正向源宽高归一化），而非仅保存相对自动构图的缩放和偏移。完整跟踪可以更新人物轨迹，不得根据后来的人体大小分位值或全局运动范围覆盖此矩形。运镜保持用户选定的镜头高度与纵向位置，以目标相对参考时刻的横向位移平滑跟随；参考时刻用等式约束锁定水平位置。非分析采样时刻加入精确节点，渲染轨迹保留该节点。

明确的手动构图优先；后续动作超出固定视口时提示限制，不在处理完成后静默扩大镜头。全身保护约束手势与可实现的水平跟随。完成／取消／撤销恢复完整锚点状态；自动重置、更换目标或裁掉锚点时刻会清除锚点，身份异常重新确认保留原构图。计算未完成时不能提交旧视口。验证必须同时覆盖「处理前实际编辑画面→处理后预览→导出成片」，只比较处理后预览和成片不能视为构图功能验收通过。


## 人物打码（2026-10-19）

- 编辑工具增加「打码」，仅用于跟随主角之外的人物；开启后自动遮挡主角以外的全部人物，无需逐人选择；新进入画面的人物自动纳入。更换主角时使遮挡轨迹失效，预览与导出均校验主角排除规则。保持单页不滚动，强度按需展开，取消恢复进入工具时的设置和轨迹。
- 范围：人脸（保守覆盖头部，包含侧脸余量）、整个人物（覆盖手脚的矩形区域，非人体轮廓分割）。
- 样式：默认毛玻璃，可选马赛克或相册图片，三者互斥且只渲染当前选中项。图片保持比例，裁去透明留白后适度放大填充遮挡范围，保留图片透明轮廓，不添加黑色底、外部阴影或额外模糊，不叠加毛玻璃或马赛克；选图统一处理方向并压缩为最长边 512 的 PNG，随项目保存。旧项目可兼容解码。
- 不接入 Apple Vision。复用 YOLO26s-pose 鼻、眼、耳、肩关键点和人物保护框；复用 TrackTrack、OSNet 与身份门控。主跟踪分析产生的检测与外观特征供所有打码人物共享；修改样式、强度或图片不使人物轨迹失效。
- 遮挡轨迹使用原片归一化坐标和绝对时间。按已确认的主角轨迹逐帧排除主角，剩余人物共用一个 TrackTrack 实例。短暂漏检保留最多 0.6 秒预测遮挡；人脸关键点不可见时保守覆盖上半身，不因转头直接撤除遮挡。长时间离场后结束对应轨迹，重新出现时自动新建。主角身份仍按既有流程处理歧义。
- 离线短时前瞻、观测包络、双向缓慢收缩及逐帧插值，保持遮挡连续。马赛克网格固定在原片坐标，避免纹理随框游走；三种样式共用同一遮挡轨迹。
- 预览和导出共用 RedactionCompositor，统一应用原片方向、构图轨迹和遮挡轨迹；模糊采样保留裁剪边缘之外的原图上下文。显式设置 Rec.709 帧色彩标记。未启用打码的项目继续原导出路径。
- 完整轨迹生成之前提供暂停帧设置预览，完整播放在处理完成后开放，避免将固定选人框误当作跟踪结果播放。
- 验证证据位于 docs/validation/redaction/：三种样式、三种构图比例的预览与实际导出一致性，透明图片无黑色补底、图片放大覆盖，边界连续性、遮挡阻塞与恢复，桌面 3840×2160 原片片段、多目标共享检测与模拟器相册选图导出。性能记录仅代表所测短片段及当前模拟器，不能换算为真机持续帧率。


### 返回编辑后的生成规则（2026-10-19）

- 主角选框统一显示「主角」，处理与暂停状态放在页面进度控件中。
- 保存生成配置快照，包含项目、源文件、元数据、主角及选择时间和全部编辑设置。与当前快照不一致时，编辑页按钮显示「重新生成」。
- 修改后留在编辑页按新配置渲染实际视频，并显示进度；完成后才进入导出完成页。主角与时间范围没有变化且轨迹完整时复用分析结果，不重复运行人物识别。
- 未修改配置、仅查看构图或取消设置时，仍可复用已有成片；取消打码设置也保留此前的成片文件与保存状态。

## iPhone Duo 与 Mac 适配（2026-10-19）

编辑与导出采用同一视频／操作双区域容器。iOS 27.1 正常宽度使用系统 ArrangementView 分离区域并响应折叠区域；紧凑宽度及旧系统按当前容器空间使用 AnyLayout，上下／左右布局转换时保留应用模型与编辑设置。编辑页不滚动，安全区由系统处理，不按设备名称判断布局。

Mac 采用 Mac Catalyst 复用 YOLO、TrackTrack、OSNet 和导出实现。支持 Intel 与 Apple Silicon 构建；Intel 的半精度张量通过 Core ML 数组访问器读取，避免不受支持的 Float16 原生转换。提供安全范围文件导入（先复制应用私有副本）、系统文件保存面板、空格播放、⌘O 导入、⌘S 保存成片，视频不整段读入内存。窗口最小尺寸 720×560；首页列表和导入入口限制内容宽度。

验证：Duo 关闭／半展开／展开与构图连续性；旋转 UI 测试；普通 iPhone 的 95 项单元与集成测试（6 项按条件跳过，无失败）及 2 项 UI 测试；Mac 实际导入桌面 3840×2160、37.92 秒原片，完成整段跟踪、1080×1920 导出与系统保存，保留原音。Intel 仅完成构建，实际运行在 Apple Silicon。证据见 docs/validation/adaptive-workspace/。

### Mac 桌面工作台重设计（2026-10-19）

- 项目库使用固定侧栏与自适应卡片网格，文件导入为顶部主操作，保留照片导入与删除菜单。
- 编辑器独立采用桌面布局：顶部项目与处理操作、左侧全览画布及通栏时间轴、右侧 300 pt 检查器。构图、打码设置按区段组织，不再占用画布下方空间。
- 处理与暂停在当前工作台内切换；暂停提供返回调整；异常确认仍阻塞处理。导出页采用大画布与右侧输出信息，保存到文件为主要操作。
- iPhone 与 Duo 继续使用原有自适应布局。Mac / iOS 构建通过，iPhone 比例与独立居中 UI 回归测试通过；Mac 真实视频已验证构图与打码静帧、取消恢复、成片预览、原生保存；处理和暂停使用演示数据验证。本轮没有重新执行完整真实视频识别与编码。
- 实拍与验证记录：`docs/validation/desktop-redesign/review.html`。

### iPhone Duo 布局优化（2026-10-19）

- 展开屏的原生 Arrangement 优先为画布分配更大比例，时间轴跟随画布；设置区使用标题、原位设置与底部整行主操作。外屏维持紧凑手机布局，旋转时保留人物与构图。
- 布局仅提供理想尺寸，不硬性限制原生折痕分区。已修复半折叠时因严格比例和尺寸限制导致内容消失的问题。
- 展开首页改为双列项目卡片，单张封面使用更清晰的缩略图；时间轴缩略图仍维持原尺寸。展开导出页增加信息分组并将保存操作固定在操作区底部。
- 真实桌面视频已验证导入、选人、构图、打码面板操作与无滚动。Duo 旋转连续性、演示异常确认与导出流程，以及普通 iPhone 构图和暂停返回调整回归测试通过。真实完整视频跟踪与导出编码本轮未重跑。
- 验证截图：`docs/validation/duo-redesign/review.html`。

### 三轮流程与功能 CR（2026-10-19）

1. 状态流转：复现并修复异常确认期间仍能播放、拖动普通时间轴的问题。仅编辑状态允许这些操作，保留恢复时的显式前后帧查看，Mac 同步隐藏普通时间轴。
2. 构图与打码：复现并修复已分析视频修改打码配置后进入构图报错的问题。无有效新遮挡轨迹时继续支持静态构图，禁用旧动态预览，确认后重新生成遮挡并复用人物分析。
3. 异步与交互：复现后台返回后成片播放按钮状态错误；补上场景状态同步及当前播放项结束通知，避免旧播放项通知影响当前播放。取消任务隔离、删除与自动保存、缓存失效等现有回归测试通过。

验证：完整单元与集成测试 97 项，6 项私有素材／性能按需测试跳过，0 失败；构图／打码／导出专项 18 项通过；最终异步状态回归 13 项、iPhone UI 2 项、Duo UI 2 项通过，Mac Catalyst 最终构建通过。播放结束通知已接入，本轮仅对后台返回场景单独执行 UI 断言。完整桌面视频性能基准未重跑，整人矩形遮挡在人物交叠时的精细避让限制仍存在。详细记录：`docs/validation/code-review/2026-10-19.json`。
